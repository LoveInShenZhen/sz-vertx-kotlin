

# \[vn\.py\]\(vn\.py\) CTA 下单三参数：`stop` / `lock` / `net`

> 三个参数是 `buy/sell/short/cover` 下单函数的入参，**`lock`**** 和 ****`net`**** 互斥，不能同时为 True**

## ✅ stop：是否本地停止单（条件单）

`stop=True`：这笔委托是**停止单（止损 / 止盈条件单）**

1. 网关如果支持交易所服务器停止单 → 直接发交易所托管的 stop 单（关机也有效）

2. 网关**不支持服务器 stop 单** → \[vn\.py\]\(vn\.py\) 引擎在本地内存维护，持续监听 Tick 行情；价格触发后才向交易所发真实限价委托（**本地停止单**）

本地停止单特点：

- 存在本机内存，**程序断连、电脑关机直接失效**

- 触发依赖 Tick 推送，有行情延迟，存在滑点风险

- 未触发前交易所看不到委托，不会暴露止损价位

`stop=False`：普通限价单，直接发到交易所。

> 举例：`self.short("rb2610.SHFE", 3800, 1, stop=True)`：价格跌到 3800 才触发做空，就是本地止损开空。
> 
> 

## ✅ lock：锁仓模式（多空双向持仓）

`lock=True`：开启**锁仓委托转换**，优先平昨仓，剩余部分用**反向开仓代替平今**，实现锁仓（手里同时持有多仓 \+ 空仓）

- 适用场景：上期所品种，平今手续费很高；不想平今，宁愿多付保证金锁仓，规避高额平今手续费

- 逻辑示例：已有 1 手今多，想平仓 1 手；lock=True → 先看有没有昨多，没有昨多，就**开 1 手空单锁仓**，而不是发平今委托

- 账户持仓：同时有多、空双向持仓，保证金双向占用

`lock=False`：正常开平，有仓就直接平仓（优先平今 / 平昨按交易所规则），不会反向开仓锁仓。

> ⚠️ lock 和 net 不能一起开。
> 
> 

## ✅ net：净仓模式（自动计算净头寸）

`net=True`：**净持仓委托转换**，引擎自动根据当前账户总持仓净头寸，自动把策略的买卖信号翻译成开平委托，不关心今仓 / 昨仓，只关心净多净空

- 净仓含义：账户只保留一个净头寸，要么净多、要么净空，不会同时多空都有

- 逻辑：策略发`buy`，引擎先算当前净空多少，优先平空；如果还有剩余，才开多。策略只需要表达 “目标净头寸”，不用自己管理开平。

- 适合：中金所、大商所、郑商所等**净持仓账户**（账户本身不支持锁仓，只能净头寸）

`net=False`：不自动转换，策略必须自己明确是开仓还是平仓。

# 快速对比

|参数|True 含义|核心风险 / 注意点|
|---|---|---|
|stop|停止条件单（本地 / 服务器）|本地 stop 断电失效、Tick 延迟滑点|
|lock|锁仓模式，反向开仓替代平今|占用双倍保证金，上期所平今手续费场景|
|net|净仓模式，引擎自动转换开平|账户必须是净持仓模式，不能和 lock 同开|

# 常用搭配

1. 普通 CTA 趋势策略（上期所，不锁仓）：`stop=False, lock=False, net=False`，自己管理开平

2. 上期所策略，想避免平今高额手续费：`lock=True, net=False`

3. 股指 / 郑商所，账户净持仓，策略只输出目标仓位：`net=True, lock=False`

4. 止损开仓：`stop=True`，配合 lock/net 按需选择

# 一句话总结

- `stop`：**什么时候发单**（等价格触发再发，条件单）

- `lock`：**怎么平仓**，平不掉就反向开仓锁仓（多空共存）

- `net`：**自动算净头寸**，引擎帮你决定该开还是平（只留净仓）
